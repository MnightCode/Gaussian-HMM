## 1. Загальний опис моделі

Мета: **модель детекції режимів, що ротує між двома факторними моделями**. Gaussian HMM
класифікує кожен торговий день у 1 з **3 прихованих станів** (bull / neutral / bear) за
двома ознаками S&P 500 (волатильність + дохідність). Виявлений режим щодня визначає, яку
факторну модель тримати. HMM перенавчається **щодня**.

### 2.1. Ознаки (observations) HMM — вектор довжини 2, **порядок `[Volatility, Return]`**

Код формує `obs[i] = [Volatility[i], Return[i]]` — **волатильність першою, дохідність другою**.
Це важливо для точного відтворення емісійних µ/σ.

1. **Денна дохідність** — 🟩 проста, **у відсотках (×100)**:
   `Return_t = ((Close_t − Close_{t−1}) / Close_{t−1}) · 100`

2. **Волатильність** — 🟩 популяційний **MSE цін закриття відносно їх 10-денного SMA**:
   - `MA10_t = mean(Close_{t−9 … t})` (ковзне середнє 10 останніх цін, рекурсивно: `ma_sum = ma_sum − Close_{t−10} + Close_t`).
   - `Volatility_t = (1/10) · Σ_{j=0..9} (MA10_t − Close_{t−j})²`
   - Ділення на **10** (population, не n−1); одиниці — квадрат ціни.

3. **Warm-up:** перші 10 днів заповнюються нулями, потім **відкидаються** (`prices=prices[10:]`,
   `Volatility=Volatility[10:]`, `Return=Return[10:]`). Волатильність/дохідність доступні з дня 10.

### 2.2. Попередня обробка
Масштабування/стандартизація ознак **НЕ застосовується** (окрім вбудованого ×100 для дохідності). 🟩

## 3. Повний pipeline (від сирих даних до режиму)

```
(1) SPY close (2718 денних барів).
(2) Return_t = ((C_t − C_{t−1})/C_{t−1})·100.
(3) Volatility_t = (1/10)·Σ_{j=0..9}(MA10_t − C_{t−j})²,  MA10_t = mean(C_{t−9..t}).
(4) Відкинути перші 10 днів (warm-up). obs[i] = [Volatility[i], Return[i]].
(5) GaussianHMM(n_components=3, covariance_type="full", n_iter=75).  model.fit(obs).
(6) predictions = model.predict(obs)   # Viterbi-декодування.
(7) today_regime = predictions[-1].
(8) Для кожного стану зібрати його Volatility/Return; визначити:
        bear = argmin(mean(Return_state)),  bull = argmax(mean(Return_state)).
(9) Для кожного стану: KS-підбір розподілу окремо для vol і для ret;
        обчислити PDF поточних Volatility[-1] і Return[-1] за розподілом стану.
(10) Якщо  vols[today]/Σvols ≥ 0.3  І  rets[today]/Σrets ≥ 0.5:
         режим = 'bear' (якщо today==bear) інакше 'bull';   інакше режим = 'neutral' (тримати поточне).
(11) 'bear' → Modified Fama–French (market-neutral);  'bull'/'neutral' → Value/Growth (1.8x long-only).
(12) Повтор ЩОДНЯ (rebalance AfterMarketOpen).
```

## 5. Правила класифікації (маркування) режимів — 🟩

За кодом (функція `train`), на кожному перенавчанні:
- Згрупувати `Volatility`/`Return` за передбаченим станом.
- **`bear` = стан з мінімальною середньою дохідністю** (`argmin mean(regime_ret[i])`).
- **`bull` = стан з максимальною середньою дохідністю** (`argmax mean(regime_ret[i])`).
- Третій стан явно не маркується як «neutral»-стан: **`neutral` — це РЕЖИМ РІШЕННЯ**
  «низька впевненість → тримати поточне», а не окремий HMM-стан.

**Фактичні характеристики режимів на навчальному періоді (PDF Table 3):**

| Регіон | Occurrence | Avg Daily Return | Avg Volatility | Інтерпретація |
|---|---|---|---|---|
| 0 | 0.4237 | 0.0398 | 3.4739 | боковий «kangaroo» |
| 1 | 0.4463 | 0.04635 | 0.9438 | стабільний **bull** |
| 2 | 0.13 | −0.066 | 13.63465 | високоволатильний **bear** |

## 6. Механізм детекції перемикання — 🟩 (код + PDF розділ 3.5.2)

Для кожного стану окремо підбирається розподіл до **волатильності** та до **дохідності**
через **тест Колмогорова–Смирнова** (`scipy.stats.kstest`, вибір за max p-value). Кандидати
розподілів **у коді** (`Distribution.dist_names`):

```
['norm','lognorm','expon','gamma','beta','rayleigh','norm','pareto']
```
(⚠️ у коді додано **`rayleigh`** і **дубльовано `norm`**; текст статті перелічує лише
normal, lognormal, pareto, gamma, beta, exponential — див. розділ 11.)

Далі за PDF підібраного розподілу оцінюється поточна точка, і рішення приймається за
**нормованим** критерієм (точна формула з коду):

```
if vols[today_regime] / sum(vols) >= 0.3  AND  rets[today_regime] / sum(rets) >= 0.5:
        return 'bear' if today_regime == bear else 'bull'
else:
        return 'neutral'
```

- `vols[i] = PDF_vol_i(Volatility[-1])`, `rets[i] = PDF_ret_i(Return[-1])`.
- Нормування — **частка PDF поточного режиму в сумі PDF по всіх режимах**; пороги
  **0.3 (волатильність)** та **0.5 (дохідність)** мають виконуватись **одночасно**.
- `Distribution.Fit` викликає `dist.fit(y)` для кожного кандидата, `PDF` — `dist.pdf(x, *params)`.

## 8. Факторні моделі та ротація — 🟩 (з коду `HMMHybrid`)

**Всесвіт (universe):** Coarse — топ **300** за `DollarVolume` серед паперів із фундаменталом
і `Price > 1`. `num_fine = 50` (по 50 у long/short).

**Дві робочі моделі (між якими ротує стратегія):**

- **`GrowthModel`** (у коді) = **Value-модель статті**, **long-only, леверидж 1.8x**
  (`SetHoldings(i, 1.8/50)`). Fine-відбір за 4 факторами (rank-бакетинг `ceil(rank/num_stocks)`,
  сума, сортування спадно, топ-50):
  1. `TotalDividendPerShare.ThreeMonths` — спадно (найвищий дивіденд),
  2. `PriceChange1M` — **зростанням** (`reverse=False`, тобто найменша/найбільш негативна зміна → mean-reversion),
  3. `BookValuePerShare` — спадно,
  4. `FCFYield` — спадно.
  Застосовується у режимах **bull / neutral**.

- **`FamaFrench`** (Modified Fama–French, **market-neutral long/short**): long +1/50, short −1/50.
  Fine-відбір за 3 факторами (кожен вага 0.33, сортування за зростанням суми):
  1. `PriceChange1M` — спадно,
  2. `PBRatio` — спадно,
  3. `MarketCap` — зростанням (найменша капіталізація).
  Long = топ-50, short = нижні-50. Застосовується у режимі **bear**.

**Логіка ротації (`rebalance`, щодня AfterMarketOpen):** викликати `train()` → 'bear'/'bull'/'neutral';
якщо портфель порожній — застосувати відповідну модель; якщо `next==switch` — нічого; якщо
`next=='neutral'` — тримати поточне; інакше перемкнутись (`bear→FamaFrench`, інакше `GrowthModel`).
`Reset` на початку місяця переприкладає поточну модель (щомісячне оновлення холдингів).

> Решта 4 моделі (FF3, Carhart, AQR, S&P500 ETF) у статті — **лише для порівняння** якості
> по режимах (Tables 4–7), у ротації не беруть участі.

**Найкраща модель за режимом (PDF Table 5, сер. дохідність − r_f):** Value — краща в regime 0/1;
Modified FF — краща в regime 2. Узгоджується з ротацією.

## 9. Технічний план реалізації (без коду)

1. **Дані:** SPY, денні close, ~2718 барів історії на кожне навчання (+ warm-up 10 днів).
2. **Ознаки:** `Return=((C_t−C_{t−1})/C_{t−1})·100`; `Volatility=(1/10)Σ_{j=0..9}(MA10−C_{t−j})²`; відкинути перші 10 днів; `obs=[Vol, Ret]`.
3. **HMM:** `GaussianHMM(n_components=3, covariance_type="full", n_iter=75)` (решта — дефолти); `fit` → `predict` (Viterbi).
4. **Rolling:** перенавчання щодня на останніх ~2718 барах.
5. **Маркування:** bear=argmin mean(ret), bull=argmax mean(ret).
6. **Детектор:** для кожного стану KS-підбір (`norm,lognorm,expon,gamma,beta,rayleigh,norm,pareto`) окремо на vol і ret; PDF поточної точки; рішення `vols[today]/Σvols≥0.3 AND rets[today]/Σrets≥0.5` → bear/bull, інакше neutral(hold).
7. **Ротація:** bull/neutral → Value/Growth (1.8x long-only, 50 акцій); bear → Modified FF (long50/short50, market-neutral); всесвіт топ-300 за dollar volume; ребаланс щодня + переприкладання щомісяця.
8. **Валідація:** out-of-sample 2017-08-30…2020-04-01, cash $100k. Цільові метрики (PDF Table 4): **Sharpe 2.017, IR 1.64, Treynor 0.264, Returns 2.4491, Max DD 0.1283**; π/A → Tables 1–2; regime-статистика → Table 3.

## 12. Верифікація за трасуванням коду (3 ключові пункти)

**Джерело істини — код.** Де код і стаття розходяться → беремо код. Нижче — трасування.

### 12.1. Вікно: 2718 барів → **2708 obs** (не 2707)
- `self.History(self.symbols, 2718, Resolution.Daily)` → запит **2718** денних барів.
- `data_length = 3356` — **оголошена, але не використовується** (мертва змінна; ігнорувати).
- Warm-up додає 10 нулів; основний цикл додає значення при `i >= 10` (`i = 10…2717` → 2708 записів); далі `[10:]` відкидає перші 10 → **рівно 2708 спостережень** у `model.fit(obs)`.
- **Реплікація:** rolling-вікно = 2718 барів → 2708 obs, перенавчання щодня. «2707» зі статті — ігнорувати.

### 12.2. `neutral` — режим СТРАТЕГІЇ, а не ринковий режим (критично)
- HMM має **3 приховані стани**, але рішення мапить їх так:
  `bear = argmin mean(ret)`, `bull = argmax mean(ret)`; якщо `vols[today]/Σvols ≥ 0.3 AND rets[today]/Σrets ≥ 0.5` → `'bear'` (якщо today==bear) інакше `'bull'`; **інакше `'neutral'`**.
- `'neutral'` = **фільтр впевненості не пройдено** → у `rebalance` означає **«тримати поточне, не перемикатись»**.
- **Третій (середній) стан не має власної дії:** при впевненості він згортається в `'bull'` (→ GrowthModel).
- Отже стратегія фактично **бінарна** (Growth ↔ FamaFrench) + буфер `hold`. `neutral` **≠** окремий ринковий режим.

### 12.3. Леверидж **1.8×** (не 2×)
- `GrowthModel`: `SetHoldings(i, 1.8/50)` → 50 × (1.8/50) = **1.8× long-only**.
- `FamaFrench`: long `1/50`×50 = 1.0, short `−1/50`×50 = −1.0 → **market-neutral** (gross 2.0, net 0).

### 12.4. Перехід на поточні дані (напрям проєкту)
Архітектура коду **date-agnostic**: `train()` щодня бере «останні N барів до поточної дати».
Використання **актуальних даних** = наведення того самого rolling-window pipeline на сьогодні
(останні 2718 денних барів SPY до today). Фіксованими у статті були лише **дати бектесту**
(2017-08-30 … 2020-04-01) — методологія від них не залежить, **жоден гіперпараметр HMM не
змінюється**.
